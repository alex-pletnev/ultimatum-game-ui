# 11. Ограничения и проверки

Актуально после T-025 (2026-10-23).

## Ограничения продукта

- Профиль временный: нет пароля и восстановления после выхода. Интерфейс предупреждает и запрашивает подтверждение выхода.
- Создавать игры может ADMIN; ведущий не участвует в собственной игре. Роли backend сохранены.
- Форма создаёт командные игры с двумя командами и чётным числом мест. Игрок выбирает команду, заполненная команда недоступна. Серверная проверка вместимости и транзакционная блокировка изменений состава добавлены в backend T-107.
- Учебный раунд локален, использует заранее объяснённую стратегию и не записывается в статистику.
- Последняя игра хранится локально для текущего профиля. Полного списка личной истории нет.

## Технические ограничения

- Отдельного REST endpoint для готового счёта нет. Клиент использует публичные CSV/участников и авторизованную историю раундов. После WebSocket-событий обновления видны немедленно; резервный опрос — каждые 10 секунд.
- `SessionWithTeamsAndMembersResponse` не содержит `rounds`. Источник истории — `GET /session/{id}/rounds`.
- При неопределённом результате отправки команда не повторяется автоматически: пользователь обновляет серверное состояние. Это предотвращает случайный повтор старта/прерывания.
- JWT хранится в localStorage в соответствии с текущим Bearer/STOMP-контрактом. Не добавляйте вставку недоверенного HTML.
- При локальном запуске backend обнаружена существующая ошибка сканирования Springwolf (`@Payload` у команд без тела). Health и REST/STOMP-игра работают; исправление генерации AsyncAPI не входит в T-025.

## Проверки

Unit-тесты покрывают вход, безопасный возврат по приглашению, обучение, формы, команды и восстановление счёта. Playwright проверяет настоящий сервер на отдельной БД: две игры по ходам, ботов, команды/приглашения, обновление страницы, мобильные размеры и клавиатуру. Результаты конкретного прогона и оставшиеся ограничения записаны в `docs/tasks/T-025-simple-game-experience.md`.
